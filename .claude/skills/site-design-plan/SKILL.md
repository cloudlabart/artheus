# 사이트 디자인 계획

만들기 전에 계획을 세워 사용자에게 보여 준다. 계획 단계에서는 **파일을 고치지 않는다.**

## 먼저 읽기
1. `CLAUDE.md` 디자인 규칙, `tools/studio/brand-visual.md`
2. 관련 화면 코드(`src/app/App.tsx`의 PAGES 표, `src/app/pages/`, `src/app/components/`)와 `src/content/site.json`(실제 코치·프로그램 내용)
3. 문구가 들어가면 `content/style/voice.md`
4. frontend-design 스킬이 있으면 그 원칙(분명한 미적 방향, 템플릿 같지 않은 선택)을 참고하되, 색·모서리·keep-ko 같은 브랜드 규칙이 항상 우선

## 화면이 필요하면
`node tools/studio/shot.mjs <경로> 1440,390` 으로 지금 화면을 캡처해 Read로 보고 시작한다.

## 계획 형식 (한국어, 짧게)
```
## 목표
이 화면을 본 고등학생·대학생 연기 지망생이 무엇을 하게 되는가 (예: 상담 신청)

## 구성 (위에서 아래로)
1. 섹션 이름 — 무엇을 보여 주나 · 레이아웃(데스크톱 / 모바일) · 쓰는 컴포넌트
2. …

## 문구 방향
제목 후보 2개, 핵심 문장 톤 (voice.md 기준)

## 이미지
- 위치 · 비율 · 생성 프롬프트(영문, 브랜드 스타일은 도구가 자동으로 붙임) · alt
- 실제 사진을 써야 하는 곳(코치 사진 등)은 "실제 사진" 표시

## 모바일 (390px)
줄바꿈·순서·버튼 크기에서 달라지는 점

## 고칠 파일
src/... 목록

## 확인 필요
사용자가 정해야 할 것 (가격, 실제 수치 등 — 지어내지 않는다)
```
마지막에 "이 계획대로 만들까요?"로 끝낸다.

## 계획대로 만들 때
- 이미지는 `site-image` 스킬대로 만든다.
- 끝나면 `site-review` 스킬의 캡처로 데스크톱·모바일을 확인하고 넘침이 있으면 고친다.
