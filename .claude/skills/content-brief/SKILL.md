# 콘텐츠 브리프

입력: 주 키워드 ($ARGUMENTS). 기준: `tools/geo-seo/references/geo-seo-playbook.md`. 양식: `tools/geo-seo/templates/brief.md`.

## 절차
1. **슬러그 결정** (영문 소문자-하이픈) → `content/column/<slug>/` 생성.
2. **GSC 근거**: `content/data/gsc.csv` 가 있으면 이 키워드와 토큰이 겹치는 검색어·페이지를 추린다 (노출, 순위, 현재 랭킹 URL). 이미 랭킹 중인 URL이 있으면 브리프 유형을 "기존 글 보강"으로 바꾸고 그 페이지 본문을 가져와 비교한다.
3. **리서치** — `seo-researcher` 에이전트에 위임 (키워드, 보조 검색어 목록, 사이트 도메인 전달). 에이전트가 반환할 것:
   - 구글 상위 5–10개: 제목, 형식, 다루는 하위 주제, 빠진 것
   - AI Overview/AI 답변 요지와 인용 도메인 (ChatGPT·Perplexity 스타일 질의로 웹검색해 확인)
   - 네이버: 연관검색어, 스마트블록 주제, 상위 블로그 공통 구성 (web-fetch로 `https://search.naver.com/search.naver?query=<키워드>` 시도; 막히면 웹검색 결과로 대체하고 "추정"으로 표시)
   - 1차 출처 후보(공공기관·통계·공식문서) URL과 각 출처의 핵심 수치
   - 실제 사람들이 묻는 질문(PAA, 지식iN, 커뮤니티) 8–15개
4. **청중 구체화**: config.editorial.audience 를 바탕으로 이 글의 '청중 한 문장'(누가·언제 검색·읽고 무엇을 할 수 있어야 하나)과 예시 소재 2–3개를 정한다. 솔루션은 3–5개만 고르고, 추천 도서 2–3권을 서지 확인 후 브리프에 적는다.
5. **의도 판정**과 **Information Gain** 정의: 경쟁 글에 없고 우리가 줄 수 있는 것 1–3개 (자체 데이터·경험·계산기·비교표). config의 brand/author 전문성과 연결.
6. **아웃라인**: H2는 질문형 우선, 각 H2에 "첫 문장 답 / 넣을 수치·출처 / 표·목록 여부"를 적는다. FAQ 3–6개, 스키마 유형(Article+FAQPage, 단계형이면 HowTo).
7. **메타 초안**: 제목 후보 3개(15–45자, 키워드 앞), 메타 설명, 태그 5–10개, 목표 분량.
8. `brief.md` 저장 후 핵심(의도·차별점·아웃라인 H2 목록)을 사용자에게 보여준다. 단독 실행이면 "이대로 작성할까요?" 확인.

## 품질 기준
- 출처 없는 수치는 브리프에 넣지 않는다. 수치마다 URL과 확인일.
- 조사가 막힌 부분은 숨기지 말고 "미확인"으로 남긴다.
